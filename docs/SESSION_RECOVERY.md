# 接続調査と同じ部屋への復帰

## 2026年10月11日の調査

報告は「操作中にも約15〜20分で切れる」「コンピュータ1人が参加していた」。Render管理画面の契約・起動記録は確認できましたが、切断した正確な時刻、端末の通信記録、当時の切断理由は残っていないため、過去の直接原因は未確定です。

公開WebはVercel、ゲームのSocket.IO通信は直接Render（`title-kakko-kari.onrender.com`）へ接続していました。両方の公開リリースは `8ae81f39b330`。GitHubやVercel Functionsをゲーム通信が通り続ける構成ではありません。コンピュータ回答は提出開始時にローカルで生成され、別の接続や15分のタイマーを持ちません。

Renderは[WebSocketに固定の最大接続時間を設けていません](https://render.com/docs/websocket)。[無料Webサービスの休止条件](https://render.com/docs/free)は15分間の受信通信なしで、既存WebSocketからのメッセージも通信として数えます。そのため「15分程度」という時間だけで無料契約による休止と断定できません。端末の休止、通信の中断、サーバーの置き換えなどを切断記録と照合する必要があります。

所有者のログイン後、Render管理画面で対象サービスのComputeが **Free、月額$0、0.1 CPU、512 MB RAM** と確認できました。Disk画面は「無料プランでは利用不可」で、永続ディスクはありません。VercelとGitHubの料金プランは取得できていませんが、ゲームの継続通信はそれらの実行時間制限を通る構成ではありません。

Renderの直近7日の起動ログでは、2026-10-10 15:18:47・23:15:56、10-11 00:11:36・01:00:15・01:54:11 JSTにサーバーが起動しています。00:11と01:00はそれぞれmainへの自動デプロイに対応し、01:54は本調査の初回接続付近です。自動デプロイはプレイ中でもサーバーを置き換える可能性があります。デプロイ以外の再起動・障害・保守等のイベントを絞ると、過去90日の該当表示はありませんでした。ただし休止・全切断理由が網羅的に記録される証拠ではなく、報告された切断との時刻照合もできません。従来のアプリには接続ごとの切断理由・稼働時間の記録がありませんでした。

現行公開版をChromiumの独立した7ブラウザーで検証しました。人間4人の部屋と人間3人＋コンピュータ1人の部屋を提出段階で放置し、2026-10-11 01:57:43〜02:22:43 JSTの25分（実測1,500,003ms）で、両方とも切断なし・同じ部屋・回答フォームを保持。放置後の提出・投票・MVP選出も成功しました。放置中の画面操作、health監視、独自keepaliveはなく、通常のSocket.IO ping/pongだけが継続しました。終了後は検証用の参加者が明示退出しました。この一回で全端末・全通信状態の切断がないことまでは証明できません。

## 確認できた問題と修正

従来の公開版には、一度切れると部屋・席を復元する経路がなく、サーバーのメモリも再起動で失われる問題がありました。本変更は切断理由を記録し、切断からの復帰とサーバー保存を追加します。

- 通信断では参加席、ホスト・出題者の役割、ラウンド、宣言、提出、投票、得点、MVPを保持します。出題者が通信断しただけではMVPを他の人へ渡したりゲームを終了したりしません。
- Socket.IOの2分の通知再配信が終わっても、非公開の復帰情報で現在の段階を取得できます。再読み込み後は「前の部屋に戻る」を使います。同じブラウザーで保存した部屋番号と名前で参加しても復帰を試します。
- 部屋番号は共有できますが、席の復帰にはランダム256bitの本人専用トークンも必要です。サーバーはハッシュだけを保存し、他の参加者へ配信しません。正解・未公開の回答は出題者専用の復帰応答にだけ含めます。
- 同じ席に別の画面から復帰すると、新しい画面へ接続を移します。明示退出はトークンを無効にし、従来のホスト引き継ぎ・人数不足時の終了を行います。オフラインで退出した場合、ブラウザーの復帰情報は消えますが、その時点でサーバーへの退出通知は届かず、席は期限まで残る場合があります。
- 最後の人間がオフラインになってから24時間で期限切れです。人間が接続中の部屋は時間経過だけで削除しません。コンピュータだけでは期限を延長しません。
- healthにはランダムな起動識別子と稼働秒数を追加します。切断ログには識別子・切断理由・接続秒数だけを出し、部屋番号・プレイヤー識別子・タイトル・トークン・URLを記録しません。次の切断時に、サーバー再起動と端末側の切断を区別するための情報です。

## 保存と運用上の境界

既定の保存先は `server/data/rooms/state.json`、変更は `ROOM_STATE_PATH` で行います。仮ファイルを書き終えてから置き換え、操作を保存してから成功応答を返します。破損した保存ファイルは空の部屋一覧で上書きせず、起動を止めて保全します。部屋の回答や本人認証のハッシュを含むため、Web配信・Git・公開成果物に含めないでください。

保存は**単一プロセス・単一インスタンス**専用です。ファイルが残る保存先なら、プロセスを強制終了して再起動しても復帰できます。確認したRender Freeの通常のファイル領域は再起動・休止・再デプロイで失われるため、本実装だけではその領域の消失に耐えられません。[Renderの永続ディスク](https://render.com/docs/disks)など、実際に残る保存先へ配置し、その公開環境で再起動・復帰を検証する必要があります。無料サービスには永続ディスクを追加できません。管理画面の最小有料Computeは月額$7で、ディスク代は別です。料金変更や保存リソースの作成、このブランチの本番反映は本調査では実施していません。

確認したRenderのRoot Directoryは `server`、Start Commandは `node src/index.js` です。永続ディスクを採用する場合は、既定保存先の親ディレクトリ `/opt/render/project/src/server/data/rooms` をマウント先にできます。ここに置けば `ROOM_STATE_PATH` の本番変更は不要です。ディスクは同時に1インスタンスだけで使い、公開反映の際は進行中の部屋を保護する手順を別途確認してください。これは設定候補であり、まだ適用していません。

Webの復帰情報はブラウザーのlocalStorageを使用します。別端末・別ブラウザーや保存情報の削除後は同じ席へ復帰できません。localStorageが使えない環境とネイティブ版はアプリ起動中の記憶へ退避し、アプリ自体の再起動後の保存は未対応です。アカウント登録・新しい保存サービスは導入していません。

## 検証

`tests/game-e2e.cjs` は出題・採点・MVP制限・両通信方式の短時間復帰を検証します。`tests/session-recovery.cjs` は実サーバーで本人認証、他席・不正トークンの拒否、各段階の復元、全員切断、保存先を維持した別プロセスへの強制再起動、明示退出、期限切れ、破損ファイルの保全を検証します。

`npm run test:session-soak --prefix server` は別の一時保存領域で25分の実時間試験を実行します。人間4人のpollingと人間3人＋コンピュータ1人のWebSocketを比較し、放置後の回答・投票・MVP・次ラウンドまで確認します。通常のテスト実行には長時間待機を含めません。

修正版の実時間試験は2026-10-11 02:14:22〜02:39:22 JST、実測1,500,217msで切断0、両部屋とも次ラウンドまで成功しました。実ブラウザーでは宣言・提出・投票・MVP段階の再読み込み、全員130秒の通信断後の自動復帰、保存領域を維持した強制プロセス再起動後の同じ席・得点・MVP復元を確認しました。デスクトップ1440×1000とモバイル390×844で、出題者専用の正解・回答表示とMVP未確定時の進行禁止を検証しています。

ローカルのビルド・テスト、現行公開版の診断、本変更の公開反映は別の確認です。現行公開版の25分試験は、本変更を公開した後の復帰検証の代わりにはなりません。
