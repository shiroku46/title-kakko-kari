## 今回の候補に含む変更

- ブラウザで投票失敗・タイムアウトを画面内に表示し、送信中の重複操作を防ぐ。
- 自分の偽タイトルを投票画面で無効にし、答え合わせで「あなたのタイトル」を表示する。
- 固定作品リストに依存せず、Wikipediaのカテゴリ・全文検索、青空文庫目録、国立国会図書館サーチを継続探索する。
- 漫画・音楽・映画・アニメなど16分類を巡回し、実在作品の紹介資料から完全な文を選んで出題文を作る。筋書きがない作品には実際の内容・特徴の紹介文を使う。
- 題名・別名を伏せ、作品名・ジャンル・資料リンクは答え合わせで公開する。出題者の入力補助で編集した文章に、元資料の出典をそのまま付けない。
- 記事・資料のIDで重複を避け、同名の別作品を題名だけで除外しない。問題集と探索位置を保存し、自動補充の状況を `/health` で確認できるようにする。

最新mainの「タイトルカッコカリ」の題名画面・画像・同梱フォントを維持します。収集・要約の詳細と範囲は [AUTOMATIC_QUESTIONS.md](AUTOMATIC_QUESTIONS.md) を参照してください。

## 問題が出た場合の戻し方

- [ ] 影響を切り分け、収集だけに問題がある場合は `QUESTION_COLLECTION_ENABLED=false` で収集を停止する。これは収集済みの問題の内容を修正する操作ではない。問題集に不備がある場合は、収集停止中に確認済みの問題集・対応する探索状態へ戻す。
- [ ] Client / Serverの不整合やゲーム進行の不具合がある場合は、記録した既知の公開版の組合せへ戻す。Serverの従来版の確認済み識別子は `809a76c2f019`。Webの復旧先は記録済みProduction `6782241032`（SHA `eead2f3036571a5468d9d4960d30303907ae4447`）を使う。
- [ ] ファイルを復元する間は収集プロセスを止め、問題集・探索状態を一組として扱う。一時ディスクにデータが残らない場合は、同梱初期データからの起動を確認する。ソースの初期問題集や旧検証記録を削除しない。
- [ ] 戻した版のHTTP・health・題名を確認し、4人のプレイヤー出題を最終順位まで再確認する。再起動で部屋と得点が失われるため、参加者には新しい部屋を作ってもらう。原因・復旧先・確認結果を対象リリースに記録する。

## 運用上の境界

- 単一プロセス・単一インスタンスで運用します。
- Renderの再起動、休止、再デプロイ時には部屋と得点が失われます。
- 最後の参加者が切断すると部屋を削除します。
- 画面更新後の本人確認付き復帰、ゲーム履歴、途中再開、複数インスタンスでの状態共有は未対応です。
- Renderが休止状態の場合、最初の接続に時間がかかり、休止中は自動収集も動きません。
- 収集データを保持できるかは保存先の運用条件に依存します。今回の候補だけで再デプロイを越える永続性や運用費用は保証しません。
