# タイトルカッコカリ｜最初の画面の制作方針

更新日：2026-10-01

対象：[Issue #55](https://github.com/shiroku46/title-kakko-kari/issues/55)。名前・ロゴ・同梱フォントの決定は [Issue #51](https://github.com/shiroku46/title-kakko-kari/issues/51) を引き継ぐ。

共通の実装基準：[UI_DESIGN_SPEC.md](UI_DESIGN_SPEC.md)

## 名前と採用した見本

正式名は **タイトルカッコカリ**、画像ロゴは **タイトル（仮）**。アプリ名、ブラウザーの題名、ロゴの読み上げ名には正式名を使う。過去の資料や引用元の名前は当時の記録を保つ。

今回の見本は `/workspace/generated_images/exec-91a96633-34df-4fbf-bafc-78180a6505fd.png`。ユーザーが採用した短い説明と3段階の見本を保ち、最後の指摘に合わせて背景を暖かいクリーム色にし、あらすじの紙の余白を広げる。

見本全体を一枚の画像として表示しない。ロゴと猫だけを独立した画像にし、説明、見本の題名、入力欄、ボタンは実際の文字と部品で組む。

## 画面の要素

| 要素 | 内容・扱い |
| --- | --- |
| ヘッダー | 正式名、遊び方、接続設定 |
| 大きいロゴ | `GameLogo` と `client/assets/brand/title-logo.png`。縦横比を保つ |
| 短い説明 | 「ウソを考えて、本物を当てる。」 |
| 猫 | `client/assets/brand/home-cat.png`。濃紺の猫1体と白い物語カード3枚。操作しない装飾 |
| 遊びの見本 | 映画・小説・漫画・ゲームを切り替え、同じ3段階の流れを見せる |
| 3段階 | 「1 あらすじ」→「2 ウソをつくる」→「3 本物はどれ？」 |
| 人数の案内 | 「4〜6人で遊べる ・ 知らなくても遊べる」 |
| 参加面 | 「ゲームをはじめる」、ニックネーム、部屋をつくる、部屋に入る |
| 補助操作 | 遊び方を見る、接続設定の開閉、はじめの設定に戻す |
| フッター | 正式名と「言葉で、あそぶ。」 |

長い説明文や、ジャンル別の大きな見本を何段も並べない。タブは**遊びを紹介する見本だけ**を切り替える。本番の問題のジャンルを選ぶ機能ではない。

## 見本の文章と操作

初めは映画の見本を表示する。

> 車のタイムマシンで30年前へ行った高校生。両親の出会いを邪魔してしまい、自分が生まれない未来を変えようとする。

ウソをつくる紙には **BACK TO TOMORROW** を表示する。本物を選ぶ3枚の紙は、最初は同じ見た目にする。

- タイム・リターン
- バック・トゥ・ザ・フューチャー
- BACK TO TOMORROW

見本の題名を押すと、その場で短い答えを出す。本物を選んだときだけ正解を知らせ、別のウソなら本物の題名を知らせる。自分が作ったウソとして示した `BACK TO TOMORROW` を押すと「自分が考えたウソは選べないよ。」と知らせ、投票先にはしない。タブを切り替えると選択と答えの表示を消す。

小説・漫画・ゲームにも、作品の内容に合った紹介と、ありそうな英語のウソを用意する。文章と題名の正本は `client/src/components/home/examples.js`。この見本はゲームの得点や部屋には触れない。

## 色と文字

| 用途 | 基準 |
| --- | --- |
| 画面全体の背景 | 暖かいクリーム `#FFF1D6` |
| 見本・副ボタン・設定の面 | 明るいクリーム `#FFF7E8` |
| あらすじ・題名の紙 | 白。紙の外にはクリームの背景を残す |
| 見出し・輪郭 | 濃紺 `#0B2D4D` |
| 主なボタン | 赤 `#EB4057` と白い太字 |
| 本文・入力 | 同梱の Noto Sans JP Regular、400 |
| 見出し・ボタン | 同梱の Noto Sans JP Bold、700 |

あらすじの紙は左右にも余白を取り、文章を端まで詰め込まない。縦並びでは16px／行間27px、横並びでは18px／行間29pxを使う。紙の内側の余白は縦並び22px、横並びでは左右24px・上下22px。

文字は他画面と同じ Regular／Bold を使う。以前集めた丸い文字や手書き風の文字は別案として保存する。利用条件と変換方法は [FONTS.md](FONTS.md) を参照する。

## パソコンの配置

幅1200px以上では、左にロゴ・短い説明・猫と3段階の見本、右に参加面を置く。全体の最大幅は1586px、左右の余白は画面幅の3.6%。参加面は内容幅の30%で、左に34pxの余白と細い境界線を置く。

見本の横幅が700px以上のときだけ3段階を横に並べる。狭いときは縦にし、題名やあらすじの読みやすさを守る。左側を大きな濃紺の箱で囲まない。

## スマートフォンとタブレットの配置

幅1200px未満では、次の順に縦に並べる。

1. 正式名と遊び方／接続設定
2. ロゴ、短い説明、小さい猫
3. 名前入力と作成／参加
4. 3段階の見本
5. フッター

左右の余白は20px、幅360px未満では16px。中央の内容幅は最大720px。見本は参加面の後ろに置き、長い説明を読まなくても部屋に進める順にする。猫はロゴの横で小さく表示し、ボタンを押し下げる大きな絵にしない。

## 操作と失敗時の動き

名前が空のとき、部屋コードが6けたでないとき、接続先の書き方が違うときは入力欄の近くで知らせる。参加に切り替えても名前は残す。部屋コードは数字だけを最大6けたまで受け付ける。

接続中は二重に送れないようにし、「やめる」で接続を止めて入力へ戻れるようにする。サーバーの起動待ちは最大90秒、接続と部屋作成・参加の返事待ちは各10秒。返事がない場合は画面内に知らせ、もう一度試せる状態へ戻す。取り消した要求の遅い返事で、勝手に部屋へ進まない。

ロゴには正式名の読み上げ名を付ける。猫、矢印、小さい絵は装飾として読み上げ対象から外す。入力にはラベルを付け、見本のタブには選択状態を付ける。ボタンはキーボードでも操作できるようにする。

主なボタンの最小高さは縦並び56px／横並び72px、入力欄は縦並び54px／横並び64px。本文の色の差は4.5:1以上、赤い主ボタンの大きな白い太字は3:1以上を基準にする。押せない状態、接続中、入力の間違いは言葉でも伝える。文字の読み込みに失敗した場合は端末の文字で開く。

## 確認項目

実施結果は [RELEASE_STATUS.md](RELEASE_STATUS.md) と対象PRに記録する。ここに見本の基準を書いたことだけで、確認済み・公開済みとはしない。

- 1586×992、1440×900、1024×768、768×1024、390×844、320×740で、クリームの背景、紙の余白、文字、ボタン、横はみ出しを確かめる
- 4つのタブ、見本の題名と答え、名前と部屋コード、遊び方、接続設定を確かめる
- 空欄、不正な入力、接続失敗、返事なし、接続の取り消し、文字の読み込み失敗を確かめる
- 4人の部屋作成からゲーム終了まで、CPU出題、自分のウソの選択禁止、人が抜けたときの進み方を確かめる
- 採用した画像の見本と実画面を見比べ、狭い画面で意図して変えた順序を区別する
