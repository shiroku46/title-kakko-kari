## 永続性の比較と選定

- 必要なセッション状態: 部屋コード、参加者、接続ID、順番、進行、回答、投票、ラウンド点・累積点、宣言。
- 現行仕様に再起動後の履歴閲覧・継続要件はなく、クライアントに本人確認付き復帰の通信もありません。宣言は移行前からメモリのみでした。DBの一部保存だけでは再起動復帰を保証していませんでした。
- メモリ: 追加サービス・資格情報・ファイル管理なし。同期処理で各イベントの確認と更新をまとめられる。単一プロセスと再起動時の消失が制限。
- SQLite/ファイル保存: ディスクと再起動復帰設計が必要。認証・復帰・フェーズ再送まで作らなければ継続できず、現在は不要。
- 外部DB/Redis: サービス管理と資格情報、複数インスタンスの同期設計が必要。今回の要件を超える。

**今回の実装はメモリ管理を選定。** 恒久的な永続化不要の判断ではなく、現在のMVPの最小構成です。再起動復帰または複数インスタンスが必要になった時点で見直します。

## 外部契約と整合性

既存のroom:create/join/get_state、game:start/next_round、roundの提出・宣言・投票・MVP、通知イベントの名前と既存フィールドを保持しています。roundScoresは `player_id / correct_pts / deceive_pts / total_pts`、playerScoresは `id / nickname / score` のままです。

内部配列・宣言・正解はroom:get_stateやラウンド開始通知に含めません。投票候補はID・タイトル・順番のみです。CPU確定時は既存round:synopsis_presentedを全員へ通知します。追加通知round:synopsis_fetch_failedはCPU取得失敗と再取得表示専用です。

同期更新により同時イベントの人数超過、重複回答・投票・二重採点を防止します。MVPは1ラウンド1回、投票先は現在ラウンドの候補に限定し、自分の偽タイトルへの投票を拒否します。入力は文字列型と長さを検査します（名前12、タイトル500、あらすじ10000文字）。既存UIの偽タイトル40文字制限は維持しています。

切断者の回答・投票を接続中の未提出者の代わりには数えません。進行中の切断者の得点・回答は結果表示まで保持します。空になった部屋は丸ごと破棄します。ホスト交代を画面に反映し、CPUの既取得あらすじも引き継ぎます。
