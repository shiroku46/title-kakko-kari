# Supabase撤去の監査・移行記録（Issue #37）

日付: 2026-09-05。監査元: main `20d3ebe`。仕様・制作方針: Notion「タイトルたほいや｜命名クイズゲーム制作」。実装対象: `shiroku46/title-kakko-kari`。

## 元の責務と移行先

| 元の依存 | 責務 | 移行先 |
|---|---|---|
| rooms / generate_room_code | 6桁コード、開始状態、現在・総ラウンド数 | gameState.js のMap、crypto.randomIntによる衝突確認 |
| players | ID、ニックネーム、接続、ホスト、順番、累積点 | 部屋内の参加者配列、crypto.randomUUID |
| rounds | 出題者、あらすじ、正解、フェーズ | 部屋内のラウンド配列 |
| answers | 偽回答・本物・表示順、提出重複制約 | ラウンド内配列、参加者IDの重複検査 |
| votes | 投票先と投票者、投票重複制約 | ラウンド内配列、同ラウンドの候補と投票者を検査 |
| calculate_and_apply_round_scores | 正解点と欺き点の加算 | revealRoundの同期処理、フェーズで二重採点を拒否 |
| MVPのplayers更新 | 選ばれた回答作者へ1点 | 同期加算、ラウンドごとに1回 |
| roundDeclarations（既存メモリ） | 知っている／知らない宣言 | ラウンド内Map、部屋削除と一緒に解放 |
| /health/supabase、IPv4専用fetch | 廃止するDBの診断・迂回接続 | 削除。一般の/health、/health/network、CORSは保持 |

DBのSQL定義・採点関数本体はリポジトリにありません。正解+1点と欺き票数分は既存RulesScreenと同梱PDFの8ページで確認。MVPの出題者選出・+1点は現行ゲーム実装とRulesScreenを維持しました。古いSQLの未公開内部動作との完全一致は主張しません。

## 永続性の比較と選定

- 必要なセッション状態: 部屋コード、参加者、接続ID、順番、進行、回答、投票、ラウンド点・累積点、宣言。
- 現行仕様に再起動後の履歴閲覧・継続要件はなく、クライアントに本人確認付き復帰の通信もありません。宣言は移行前からメモリのみでした。DBの一部保存だけでは再起動復帰を保証していませんでした。
- メモリ: 追加サービス・資格情報・ファイル管理なし。同期処理で各イベントの確認と更新をまとめられる。単一プロセスと再起動時の消失が制限。
- SQLite/ファイル保存: ディスクと再起動復帰設計が必要。認証・復帰・フェーズ再送まで作らなければ継続できず、現在は不要。
- 外部DB/Redis: サービス管理と資格情報、複数インスタンスの同期設計が必要。今回の要件を超える。

**今回の実装はメモリ管理を選定。** 恒久的な永続化不要の判断ではなく、現在のMVPの最小構成です。再起動復帰または複数インスタンスが必要になった時点で見直します。

## 外部契約と整合性

既存のroom:create/join/get_state、game:start/next_round、roundの提出・宣言・投票・MVP、通知イベントの名前と既存フィールドを保持しています。roundScoresは `player_id / correct_pts / deceive_pts / total_pts`、playerScoresは `id / nickname / score` のままです。

内部配列・宣言・正解はroom:get_stateやラウンド開始通知に含めません。投票候補はID・タイトル・順番のみです。CPU確定時は既存round:synopsis_presentedを全員へ通知します。追加通知round:synopsis_fetch_failedはCPU取得失敗と再取得表示専用です。

同期更新により同時イベントの人数超過、重複回答・投票・二重採点を防止します。MVPは1ラウンド1回、投票先は現在ラウンドの候補に限定し、自分の偽タイトルへの投票を拒否します。入力は文字列型と長さを検査します（名前12、タイトル500、あらすじ10000文字）。既存UIの偽タイトル40文字制限は維持しています。

切断者の回答・投票を接続中の未提出者の代わりには数えません。進行中の切断者の得点・回答は結果表示まで保持します。空になった部屋は丸ごと破棄します。ホスト交代を画面に反映し、CPUの既取得あらすじも引き継ぎます。

## 検証・残件

再実行手順と結果はREADMEとRelease Statusを参照。4/5/6人×プレイヤー/CPUの全ラウンド通信テスト、4人のブラウザ全ラウンド、切断・人数・重複・採点を確認しました。

旧Supabase接続診断・IPv4迂回専用テストは、廃止機能とともに撤去。一般のネットワーク診断、CORS、人数のテストは保持しました。新しい通信E2Eはローカル実行済みで、固定GitHub workflowは今回変更していません。

公開反映と実Wikipediaを含む公開URLのE2Eは別の残件です。Issue #37を閉じず、Draft PRでレビュー可能な状態にします。本番変更・Secret削除・デプロイはこの実装では行いません。
