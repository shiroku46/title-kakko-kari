# 出題するたびにネット検索する無料自動出題

通常起動のCPU出題とプレイヤー出題補助は、`createLiveQuestionSource` で毎回新しい検索を行い、個別作品ページを取り直して紹介文を作ります。保存問題集が空でも、存在しなくても、以前の収集が失敗していても、この経路は動きます。以前の「在庫不足→補充の待機時間→手動出題」という処理は本番の出題経路から外しました。

## コンピュータ回答者の題名

作品を取得する出題処理と、偽タイトルを提出する回答処理は別です。コンピュータ回答者は、全員に提示した紹介文と必要な回答数だけを受け取ります。正解、出典、他人の回答は渡しません。

紹介文から名詞・人名を抜いて固定語尾につなぐ方式を廃止し、出来事に対応した完成済みの題名を選びます。誘拐なら「奪われた日常」、法廷の話なら「最後の弁護」などです。時間の反復、誘拐、裁判、脱出などの具体的な出来事を、学校・会社・旅といった広い舞台より先に照合します。繰り返された周辺語句の数で優先度を上げません。記憶への言及だけでは記憶喪失、人工知能への言及だけでは宇宙旅行として扱いません。

出演者の紹介と引用された他作品名を照合から外し、最大5席へ異なる50文字以下の案を既存のシャッフルで返します。対応する出来事が見つからない短い紹介文にも、完成した題名を使います。追加料金・外部AI接続・新しい依存は必要ありません。有限の題名集から選ぶ方式なので、独自の筋、否定表現、複数のテーマの細かな関係を自由に読解するものではなく、同じ出来事に対して題名が再登場する場合があります。

## 発見と原文の照合

汎用検索はYahoo!検索、Bing、DuckDuckGoを使い、特定ドメインや固定作品名に限定しません。使用済み問題の実ジャンルを数え、小説・映画・ゲーム・漫画のうち少ないものを優先します。公式の小規模出版、単館公開、パブリッシャーによる販売等を探します。検索と並行して書店、映画作品情報、ゲームストアの現在の一覧も取得します。紹介記事から個別作品へ進むリンクは最大2段階です。

書籍では、通常の汎用検索と書店の一覧に加え、版元ドットコムの公開検索APIから現在のISBN一覧を取得します。検索エンジンや書店の応答が遅い場合も、この独立した経路から確認を続けます。過去3年の発売済み書籍をページごとに検索し、ISBNチェック桁を確かめてから個別ページを取得します。個別ページの作品名・ISBN・出版者・発売日と分類を照合し、その書籍の「紹介」欄だけを既存の品質検査に渡します。題名の振り仮名、著者プロフィール、目次、他作品の情報を紹介文に足しません。

一覧から進む書籍では、サイトの詳細画面と同じ公開の作品別JSONを取得します。一覧のISBN、作品識別子、JSONの識別子とISBNを一致させ、元の紹介欄だけを読みます。分類コードで小説と漫画を区別し、巻数付き・分類不明の資料は除外します。一般サイトの任意のJSONを作品資料として採用しません。

検索スニペットや一覧の説明を出題文にはせず、個別ページを必ず取得します。構造化データ、作品名の一致した見出し、明示された紹介節を照合します。作品名・出典URL・種類に結び付いた流通根拠を記録し、保存済み問題を選ぶときにも照合します。関連商品・おすすめ・別作品の情報から流通資格を引き継ぎません。

## 公式流通の条件

- 書籍: 当該作品の出版社、有効なISBNチェック桁、発売済みの日付を要求します。自費/自主出版・同人誌・未出版や、作者本人を出版者とする情報は対象外です。
- 映画: 当該作品の配給会社/公式配信元と公開済みの日付を要求します。制作・資金募集ページだけでは採用しません。
- ゲーム: 当該作品の有料販売、発売済みの日付、開発元とパブリッシャーを確認します。無料作品・未発売・個人制作は対象外です。開発元と販売元が同名の場合、Studio/Gamesという名称だけで法人と推定せず、法人を明示する表記が必要です。
- 投稿・自主配布サイト（カクヨム、小説家になろう、BOOTH、itch.io等）は根拠にしません。書籍化作品は出版社/書店側で確認します。
- 根拠がない/曖昧/未来の日付は除外します。紹介文の質や個人制作の根拠だけでは採用しません。

## 無名作品と文章の条件

- 公式流通の範囲で、小規模制作/出版の根拠がある作品を優先します。広い販売/評価規模や映像化の根拠がある作品は除きます。流通を確認できる認知度不明の作品は採用候補ですが、無名と断定しません。

- 作者/公式ページの紹介文から完全な文を原順序で120〜280文字抽出します。題名・別名を含む文を削除し、伏字で補いません。古語の本文、レビュー、料金、作者略歴、制作の進捗、資金募集、特典、投稿の文字数情報・読了時間・キー操作・ワークショップ案内・AI利用の開示・早期アクセス表示・作者の年齢区分/タグの注記を除きます。括弧内の句点で文を分断せず、未閉鎖の括弧の断片は出力しません。
- 明示されたあらすじが短い場合に、周囲の制作報告・作者の思い出・出演者情報を足して長さを満たしません。本文を読んであらすじを創作することもありません。見出しのない批評が続く場合も、その批評以降を長さの水増しに使いません。囲み付きの「あらすじ」ラベルも読み取り、前の収録内容・仕様と後の制作報告を混ぜません。HTMLの見出しを平文にした重複節が、見出しの境界を越えて短い物語を水増しすることも防ぎます。
- 作品ページの紹介文中で、引用符付きの名称をその作品のゲーム/小説等として明示的に定義している場合、日本語の別表記として照合し、その名称を含む文も削除します。登場人物の台詞や途中の他作品参照から別名を作りません。
- 版の表記は正規化し、番号付きの続編・部編区分は除外します。丸数字で始まる章タイトルや「序章」等も対象外です。
- 同じ部屋の使用済み問題IDを除外します。覚えるのは題名の除外キーと実ジャンルだけです。少ないジャンルは別の検索エンジン/ページで再試行してから既出ジャンルへ進みます。検索結果の実ジャンルが目的と異なる場合、そのジャンルを取得できたとは数えません。全ジャンルに有効な紹介文が見つかるときに偏りを抑える方式であり、取得先の障害時に厳密な均等比率を保証するものではありません。複数の部屋は独立にネット検索し、同じ取得中の問題を全室へ使い回しません。

「誰も知らない」という認知度そのものを測定する方式ではありません。

## 障害・負荷・取り消し

取得先が一部失敗しても別の検索先・作品・ジャンルへ進みます。429/503の待機時間はその取得先だけに適用し、過去の収集失敗で出題全体を5分/1時間待たせません。検索した作品名の在庫は持ちません。

検索と作品一覧のうち先に作品リンクが届いた経路から確認を始めます。遅い経路の結果も同じ検索内に残し、先に届いた候補が不適格でも後から届いた有効作品を取りこぼしません。作品確認は3件ずつジャンルを巡回し、未確認の候補を捨てずに次の巡回へ回します。少ないジャンルは別エンジンも含む2巡を優先し、有効作品がない場合は既出ジャンルも探してから残り候補へ戻ります。一つの候補一覧で取得上限を使い切ることを防ぎ、成功時も残った取得を取り消します。

1問は60秒、最大64リクエスト、作品ページは同時に3件まで取得します。最大8件の出題検索を同時に受け付けます。個々の取得は10秒を上限とし、成功した作品が先に確認できれば遅い同時取得を取り消します。選び直しや手動切り替えでは旧取得を取り消し、ラウンドID/版番号も照合して古い結果が次の問題を上書きしないようにします。

HTTPSの公開ページだけを取得し、DNSの全応答を公開IPか確認して検証済みのIPへ接続します。転送先も毎回検証し、最大3転送・本文2MBまでとします。認証/有料API/チャレンジ突破は行いません。再利用禁止のメタ情報も尊重します。

公開書籍検索のPOSTはJSON本文8KBまでで、転送先へ再送しません。任意の認証ヘッダーやCookieを付けず、通常のGET資料取得と同じ公開IP検証・取り消し・応答上限を使います。

外部ネットワークや取得先の全面障害時には取得失敗と再検索を表示します。架空の作品やあらすじ、有名な同梱問題で埋めません。手動出題は任意の遊び方として残します。

`/health` の `questionCollection.mode=live` と `successfulRequests` 等で稼働を確認できます。失敗時の `failure.details` には取得数・応答数・HTTP/通信エラー数・候補数・作品検証失敗数と固定の通信エラーコードだけを記録します。作品名・答え・URL・秘密情報はここには含めません。

## 従来の保存収集との関係

`server/scripts/generate-questions.cjs` 等の収集CLIと保存済みデータの検査は残します。Wikipedia・青空文庫・国会図書館などを含む16分類の継続収集はこの別経路です。本番の出題成功条件ではありません。

自動取得を明示的に止めた `QUESTION_COLLECTION_ENABLED=false` は、ローカルの保存問題を用いる再現性テスト用です。通常の本番設定は有効で、出題のたびにネットを使います。`createQuestionService({live:false})` は従来収集サービスの単体テスト/CLI互換用で、本番の初期化では指定しません。

## ジャンル指定ルール

ホストがロビーであり/なしを選び、参加者へ同期します。既定はなしで、開始後は変更できません。ありの場合は出題者（CPU出題ではホスト）が「ノンジャンル・小説・映画・漫画・ゲーム」から選んでから検索します。ノンジャンルは種類で絞らず、既存の全ジャンル検索を使います。小説は短編小説・文学作品も検索対象に含め、ゲーム中は「小説」と表示します。元資料の分類と検証根拠は変更しません。

選択は補助・CPUの確認画面・再検索・再接続でも保持し、参加者にも表示します。正解と出典は答え合わせまで伏せます。紹介文/答えを編集した場合、または取得作品と異なるジャンルに変えた場合、元資料の自動帰属を保持しません。ノンジャンルの選択や小説の分類内の変更では、紹介文・答えが元のままなら出典を保持します。選び直し/次ラウンドでは前のお題の種別表示を消します。
