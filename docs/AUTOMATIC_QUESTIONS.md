# ネットから継続収集する無料自動出題

サーバーが汎用Web検索とネット上の公開目録・作品カテゴリ・検索APIから作品を自動で見つけ、資料取得、紹介文の抽出、題名伏せ、出典保存まで行います。サーバーを通常起動すれば、作品リストの手編集や収集コマンドの手動実行は不要です。保存した探索位置から巡回を続け、収集する作品の総数に上限は設けません。同梱の初期問題は、収集開始前や資料取得障害時にも遊べるようにするためのデータです。

探索対象は共通レジストリの16分類です。物語のある作品はあらすじを優先しますが、独立したあらすじが不足する場合は資料にある作品紹介を使います。音楽・詩・美術などにも紹介文を使い、筋書きを作り足しません。

| 紹介文の選び方 | 対象ジャンル |
|---|---|
| あらすじを優先し、なければ実際の内容・特徴の紹介 | 小説、短編小説、文学作品、映画、漫画、アニメ、ゲーム、戯曲・舞台、ドラマ |
| 実際の内容・特徴の紹介 | 楽曲・歌曲、アルバム、音楽作品、詩、美術作品、ノンフィクション・書籍、その他の作品 |

この分類は候補を探す入口です。作品として確認でき、十分な紹介文がある資料だけを採用します。全作品の網羅や、各ジャンルで必ず同数の問題を生成できることは保証しません。

## 収集する資料

- **Web全体の検索**：DuckDuckGoの公開検索ページを使い、取得制限や失敗時にはBingのRSS検索を試します。検索語に特定サイトの指定や固定の作品名を入れず、16ジャンルと作品紹介・その年の新作／新刊・話題作・自主制作／インディー作品を組み合わせて巡回します。見つかったURLは複数ドメインを交互に扱い、出版社・書店・配信サービス・作品公式・作品紹介サイトなど、ドメインを固定しない公開HTTPSページを取得します。Wikipedia記事がなくても採用できます。新刊やランキングの一覧自体を問題にせず、そこから最大1段階の個別作品リンクを追加で発見します。Amazonも同じ公開ページ処理の対象で、専用の収集先や唯一の収集先にはしていません。

  作品ページのBook・Movie・VideoGameなどの構造化データ、ページ上の作品名、明示された「内容紹介」「あらすじ」「ストーリー」などの節や紹介文の領域を照合します。検索結果の短い説明やSEOの説明だけでは出題しません。紹介文は原文の完全な文から抽出し、作品名・別名を伏せます。著作者と題名・ジャンルの一致、またはISBNなどの識別情報が確認できた場合は、別ドメインの同じ作品も重複対象として扱います。書店のクエリ付きURLは資料IDを残し、同じパスの異なる書籍をまとめません。

  URL・DNS応答・転送先はそれぞれ確認し、ローカル／プライベートIPや認証情報付きURLを拒否します。検証済みIPに接続を固定し、既存のHTTPSプロキシとCA設定も維持します。HTMLは2MiBまで、取得は15秒まで、転送は3回までです。取得拒否・CAPTCHA・ログイン要求・本文の再利用を制限するHTTPヘッダー／meta指定を検出したページは採用しません。表示がJavaScriptだけで生成されるページ、短すぎる紹介、認証や有料閲覧を要する本文も取得できないことがあります。閲覧制限を回避する処理はありません。Webの本文に自由利用ライセンスがあるとは表記しません。

- **青空文庫**：公式の公開作品目録から文学作品を発見します。作品本文の抜粋は紹介文として出題しません。目録の作品名と著作者に一致するWikipediaの現代語の紹介を確認してから問題を作り、青空文庫の作品情報も参照先として残します。紹介文の出典は実際に取得した解説です。照合できない作品や、読みやすい十分な紹介がない作品は採用しません。古い作品を一律に除外する方式ではなく、現代語の紹介がある作品を扱います。サイトを限定しないWeb探索も独立して続きます。
- **国立国会図書館**：国会図書館サーチの公開APIを、資料種別・NDC分類・一般的なジャンル語で独立して検索します。本についての資料を映画と扱わないよう、図書・録音・映像などの資料種別も確認します。候補の作品名に一致するWikipedia記事を探し、冒頭の作品定義で著作者名と作品種別も確認してから紹介文を取得します。同名の別作品や作者の部分一致は採用しません。書誌に作品種別を確認できる根拠と、十分な「あらすじ：」「内容紹介：」が明示されている場合は、その紹介文から直接生成することもできます。題名・刊行年・目次・版の注記だけから内容を作りません。別途、青空文庫作品の書誌照合も行い、著者1名ごとの完全名と分かる範囲の生没年を確認して参照先を残します。画像資料のOCRやアーカイブ全文の取得・要約は行っていません。資料の閲覧条件は各アーカイブの案内に従います。
- **Wikipedia**：16分類の作品カテゴリ・下位カテゴリと、一般的なジャンル語による全文検索から候補を見つけます。作品名を固定した一覧から選ぶ方式ではありません。カテゴリ所属や検索結果だけで作品と断定せず、記事の冒頭で当該タイトルが実在作品として定義されていることを必須にします。人物・地理・企業・施設・ジャンル・一覧・曖昧さ回避・制作予定・作中だけの架空作品を除外します。物語のあらすじ節を優先し、それが不足する場合や物語以外の作品では、概要・解説・冒頭紹介から作品自身の内容・特徴が分かる文を抽出します。歌詞、詩の全文、曲目・目次、関連する別作品の紹介は避けます。転送名に加え、記事冒頭の題名に付いた読み・原題の注記から別名を取得して伏せ、取得時の版へのリンクを残します。

汎用Web検索が従来の3系統と並行して動きます。Wikipedia内の全文検索やNDLとの照合も残しますが、すべての問題をWikipediaへ照合する方式ではありません。小説・映画・ゲーム・漫画から探索を始め、残りの分類も巡回します。ジャンル別の候補を交互に確認し、同じ出典ドメインの連続も避けます。候補確認が6回続いたら未処理ページがあっても新しい検索結果を補充するため、ひとつの一覧が次の検索を妨げません。検索は1ページずつ語を変え、一覧からのリンクは1段階・最大8件です。人物、カテゴリ、共有、言語切替、ブックマーク、購入手続きなどのリンクを抑制し、個別作品ページでは紹介節の子ページに絞ります。Webページの一時失敗は2回まで再試行し、その後は次の探索周期で再発見できる形で残します。

検索サイトの順位・公開インデックス・取得制限に依存するため、「ネット全体を検索する」は検索範囲を特定ドメインに限定しない意味です。全サイト・全作品の発見や、話題性・発売日の正確な判定を保証するものではありません。

Web検索はジャンルごとに検索語の位置・検索エンジン・未処理URLを保存し、検索サイトの取得制限はジャンル間で共有します。検索の取得制限時は次のエンジンを試し、制限を受けたエンジンを一定時間避けます。一巡した検索は6時間後に再開し、新しい検索結果を確認します。他の資料系統もそれぞれ探索位置を保存します。一度の処理の取得回数・追加数には負荷制限がありますが、作品集全体の上限ではありません。次回はページ途中・カテゴリ継続位置・全文検索の位置・目録位置から続きを収集します。取得済みページの残りを保存し、少量の収集でも特定ジャンルが巡回を占有しないよう順番を回します。旧版の小説・映画の探索状態を読み込んだ場合も、継続位置を保って新ジャンルの入口を追加します。Wikipediaは探索を最後まで終えた後、7日経過後に再探索して更新を探します。NDLも探索終了後に再巡回します。青空文庫の目録は最大6時間キャッシュし、再取得で更新を確認した場合は未収集の作品を探します。

検証済みの記事・資料のIDと参照先を使って重複を避けます。題名だけで別作品をまとめないため、著作者や媒体の異なる同名作品も、それぞれの資料を確認できれば保存対象になります。随筆などは小説と断定せず、資料に応じて文学作品・書籍として扱います。

## 自動運転と保存

通常の `npm start` では、サーバー起動時と1時間ごとに収集します。その部屋で未使用の問題が少ない場合は裏で補充し、なくなった場合は新しい問題を収集してから出題します。通常の選択では検証済みの収集作品を同梱の初期問題より優先し、ジャンルと出典ドメインの組をランダムに選んでから、その組の作品を選びます。初期問題しかない場合は1回の収集完了を待ってから選び、収集障害時には初期問題で遊べます。初期問題の多さだけで有名作品が出続ける偏りを減らす仕組みで、作品の知名度を測定する機能ではありません。取得障害では保存済みの問題を使い、繰り返し失敗した場合は再試行まで間隔を空けます。収集は共有し、複数の部屋が同時に不足しても同じ収集を重ねません。

`/health` の `questionCollection` で、自動収集の有効状態、実行中か、定期処理が動いているか、最終開始・完了・成功日時、次回の定期実行予定を確認できます。失敗時は定型の理由を返し、作品名・資料URL・生のエラーは返しません。Renderなどでサーバー自体が休止している間は収集も停止し、次の起動で自動再開します。

収集した問題と探索位置の既定保存先は `server/data/questions/` です。初期問題集は `server/src/questions/bank.json`、固定カタログは明示的な手動テスト用にだけ残しています。自動収集にカタログの手編集は不要です。

保存したデータを保つには保存先のファイルシステムが再起動・再デプロイ後も保持される必要があります。Renderの一時ディスクでは収集分と探索位置が消える可能性があります。その場合も初期データから自動収集を再開します。今回の実装では有料ディスクや新しい保存サービスを契約していません。

以下のコマンドは開発・検証用です。通常運転の自動収集に実行は必要ありません。手元で1回収集する場合：

```bash
cd server
npm run generate:questions
```

既存問題に追加して保存します。再実行すると続きを収集します。1回の処理を大きくする場合、次の件数はその実行の追加目標です。

```bash
npm run generate:questions -- --batch-size 20 --max-requests 60
```

別の場所に、初期問題を使わずネットから収集する場合：

```bash
npm run generate:questions -- --output /tmp/collected-bank.json --state /tmp/collection-state.json
```

`QUESTION_DATA_DIR` で保存先を変更できます。`QUESTION_BANK_PATH` と `QUESTION_DISCOVERY_STATE_PATH` でも個別指定できます。`QUESTION_COLLECTION_ENABLED=false` はサーバーの自動収集を停止する設定です。資料取得には間隔・タイムアウト・回数上限を設け、HTTPSプロキシがある環境では設定を引き継ぐcurlを使います。

Wikipediaへの取得は最低6.5秒間隔にし、次に取得できる時刻を探索状態へ保存します。HTTP 429では `Retry-After` を確認して待機し、指定がない場合は30秒待ちます。待機中はWikipediaへの再試行を控え、Web探索や目録・NDL検索などの別処理を続けます。青空文庫候補の紹介文照合にも同じWikipediaの間隔制限を適用します。1回の収集は60秒で区切り、その間に検証できた問題と未処理の探索位置を保存して次回へ引き継ぎます。

## 要約とAI

ネットからの作品発見・目録取得・出典照合には、AIを学習させる必要はありません。通常のプログラムで行います。標準は資料の紹介文から完全な文を選び、順序を保って短くする抽出型です。表示は全自動生成経路で120〜280文字、目安200文字に統一します。長い1文を途中で切ったり、設定を作り足したりしません。手入力の紹介文にもサーバーで280文字の上限を設け、超過時はエラーを返します。

Webの紹介領域にあるレビュー、購入案内、価格・ISBN、著者略歴、ナビゲーション、関連商品、目次・表などを除き、紹介節の無関係な子見出しとその内容も抑制します。明示された画面上の紹介節を優先し、構造化データの説明文にも同じ文単位の検査を適用します。旧仮名遣い・古典文体の表現、引用だけの本文、書誌・宣伝だけの文、日本語が不足する文は出題しません。古い文を機械的に現代語へ言い換えて、未確認の解説として扱う処理はありません。

保存済み問題も取得時に同じ検査を通します。120〜450文字だった旧問題は、根拠抜粋と題名伏せの一致を確認し、完全な紹介文の範囲で短縮します。不適格な記録は出題候補から外し、保存ファイルから一括削除しません。短縮後の根拠抜粋は実際に表示する文に合わせ、出典URLと元資料のハッシュは保ちます。旧文体の検出と不要文の判定は規則によるため、未知の表記・サイト構造をすべて意味解析できるものではありません。

この方式は生成AIによる自由な言い換えや、長編の筋書きを完全に理解した要約ではありません。現代語の紹介文から、作品の題材・構成・特徴を説明する文を優先します。歌や絵画に架空の筋書きを付けません。歌詞・詩の全文、曲目や目次を紹介文として採用しないよう、節と文を検査します。資料の誤り・曖昧な分類・原文の文脈への依存は残るため、出典を答え合わせで確認できるようにしています。

Ollamaに日本語を扱える公開モデルを導入済みなら、要約に使う文の選択をローカルAIに任せることもできます。`MODEL_NAME` を導入済みモデル名に置き換えてください。

```bash
npm run generate:questions -- --ollama-model MODEL_NAME
```

接続先はローカルPCの `http://127.0.0.1:11434` です。モデルを新規学習したものではなく、既存の公開モデルを使う接続です。モデルのダウンロードは自動で行いません。API従量料金は不要ですが、PCの計算資源は使います。モデルの自由な創作文は採用せず、原文にある完全な文と順序を検証します。実モデルの推論はまだ検証していません。

## 出典と答え合わせ

### 出題する題名と除外する番号

新規のWeb・Wikipedia・青空文庫・NDL生成と保存済み問題の選択には共通の題名判定を使います。「小説 ヒトラー II 戦前篇」のような続編番号、ローマ数字、第何部、前編・後編などを含む作品は出題対象から外します。続編の番号を削って第1作の題名に置き換えることはしません。

リマスター版・オリジナル版・新装版などの版表記は、作品自体を残して基本の題名に整理します。「ストレイト・ストーリー 4Kリマスター版」は「ストレイト・ストーリー」、「STEINS;GATE(オリジナル版)」は「STEINS;GATE」です。書籍の明示された巻表示、漫画の巻数・分冊版・第何話も取り除きます。元の題名を別名として残し、基本題名と版・巻付き題名の両方を紹介文から伏せます。資料URL・取得記録・原文の根拠は保持します。

「1984」「三体」「七人の侍」「秒速5センチメートル」のように数字そのものが作品名や語句の一部である題名は一律には除外しません。題名の末尾や区切りにある番号を規則で判定するため、すべての作品の続編関係を意味解析する仕組みではありません。保存済みの不適格な問題は選択から外し、保存ファイルの一括削除は行いません。

本文の抜粋、本文のSHA-256、資料URL、取得日時、Wikipediaの版番号、青空文庫の著作権情報をサーバー側に保存します。WikipediaにはCC BY-SA 4.0のリンクを表示し、青空文庫には公式公開情報の著作権表示を付けます。

出題中の見出しは「作品紹介」に統一します。作品名、ジャンル名、資料URL、根拠抜粋、探索位置は、回答者への開始・紹介文通知に含めません。CPU確認画面も題名を伏せた紹介文のみです。答え合わせで作品名、確認できたジャンルのラベル、資料リンクを表示します。プレイヤー出題の入力補助は出題者に題名を渡しますが、題名・本文を編集した場合は元資料をその文章の出典として付けません。

`npm test --prefix server` は、ジャンル間の巡回、旧探索状態の移行、全文検索の継続位置、NDLの独立探索と題名・著作者の照合、同名別作品、物語・説明文の抽出、複数回の追加保存、取得失敗、自動補充、収集中のホスト交代と答え合わせまでのジャンル・出典非公開を検証します。Web収集については、検索エンジンの切り替えと継続位置、一覧からの個別作品発見、任意ドメインの構造化データ／紹介節、題名・別名の非公開、不正URL・DNS・転送先・過大本文・再利用制限の拒否、書籍URLのクエリ保持、初期問題からの切り替えも検証します。

2026年10月3日の実ネット検証では、汎用検索から複数ドメインの候補を取得し、見つかった出版社の新刊一覧から個別作品へ進んで3問を生成しました。集英社文芸ステーション、集英社の書籍ページ、新潮社の書籍ページでも、原文の紹介文から出典付き問題を生成して検証器への合格を確認しました。Amazonの実商品ページからの生成は未検証です。検索順位やページ形式は変わるため、この実績が今後の取得成功を保証するものではありません。

今回の品質修正では、レビュー・著者略歴・受賞や販売の宣伝が紹介領域内に混在するHTML、旧文体、長い保存済み問題、本文引用、長い手入力の拒否と修正後の送信を回帰テストで検証しました。集英社の2種類の作品ページは218文字の紹介を生成でき、青空文庫候補「走れメロス」は著作者を照合したWikipediaの現代語紹介208文字を採用できました。新潮社の確認ページは宣伝文を除くと120文字に満たないため不採用になります。同梱25問はすべて120〜280文字の完全な文で出題可能です。公開版への反映はまだ行っていません。


## 映画・ゲーム・漫画を含むWeb収集の確認

作品名を、最初のh1や記事見出しから無条件に決めません。作品の構造化データとページタイトルを照合し、公式サイトの「映画『作品名』」の形式も読めるようにします。ロゴや「予告編」の見出しは題名にしません。ページ自身の媒体表示を検索時のジャンルより優先し、映画名に「ゲーム」が含まれる場合もゲームと誤分類しないようにします。人物プロフィール、ネタバレ・考察・レビュー記事の見出し、一覧、キャンペーン見出し、雑誌号を作品として採用しません。

画像になっている節見出しは代替テキストで判別します。紹介本文のOCRやJavaScriptの実行はしません。複数の紹介節があればSTORY／あらすじを先に確認し、宣伝、限定特典、同梱物、インストール案内、ランキング情報、メディア展開の説明などを文単位で除外します。「！」と「？」の正規化後も文を区切ります。基本タイトル、巻数・版付きタイトル、ページに明示された訳名などは別名として伏せます。英文の作品名を引用する日本語の文は、引用タイトルを除いて言語を判定します。

Web問題には確認した題名・媒体・ページタイトル・識別方法を根拠として保存します。この根拠がない旧Web問題は、誤採用を引き継がないよう出題候補から外します。保存ファイルを削除することはありません。新しい検索位置へ移行するときも、旧検索の未処理URLを候補キューへ引き継ぎます。

デバッグ用のコマンドは本番の問題集を変更せず、任意ドメインの実検索から当該ジャンルを収集して検証します。タイトルや出典ドメインを固定しません。検索制限、回数・時間の上限内で適格問題が得られなかった場合は終了コード1で報告します。

```bash
node server/scripts/check-web-questions.cjs --kind film --batches 4 --max-requests 20 --output /tmp/film-check.json
node server/scripts/check-web-questions.cjs --kind game --batches 4 --max-requests 20 --output /tmp/game-check.json
node server/scripts/check-web-questions.cjs --kind manga --batches 4 --max-requests 20 --output /tmp/manga-check.json
```

実ネットで映画の公式サイト、ゲームの販売・公式ページ、電子書店の漫画ページを確認します。実際の取得成功・不採用は、ページの変更、検索順位、公開紹介文の長さに依存します。分類の巡回と取得上限は、全作品の網羅やジャンルごとの同数採用を保証するものではありません。

2026年10月3日のこの修正の実検索では、映画「ストレイト・ストーリー」「ブルーロック」「ストリートファイター／ザ・ムービー」の公式ページ、ゲーム「ラブ・スタートアゲイン」の公式ページ、漫画「お飾りの側妃ですね？わかりました。どうぞ私のことは放っといてください！」のBookLive作品ページから、それぞれ検証済み問題を生成しました。検索で見つかったXboxの「STEINS;GATE」とebookjapanの「黄泉のツガイ」「これ描いて死ね」のページでも、本文の再取得と生成を確認しました。ゲームの同梱物注記、漫画の限定特典や販売の宣伝、巻数・版を外した基本タイトルの漏れを点検して修正しました。取得記録はデバッグ用の一時ファイルに保存し、本番の問題集は変更していません。
