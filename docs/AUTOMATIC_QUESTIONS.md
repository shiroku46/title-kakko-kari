# ネットから継続収集する無料自動出題

サーバーがネット上の公開目録・作品カテゴリ・検索APIから作品を自動で見つけ、資料取得、紹介文の抽出、題名伏せ、出典保存まで行います。サーバーを通常起動すれば、作品リストの手編集や収集コマンドの手動実行は不要です。保存した探索位置から巡回を続け、収集する作品の総数に上限は設けません。同梱の初期問題は、収集開始前や資料取得障害時にも遊べるようにするためのデータです。

探索対象は共通レジストリの16分類です。物語のある作品はあらすじを優先しますが、独立したあらすじが不足する場合は資料にある作品紹介を使います。音楽・詩・美術などにも紹介文を使い、筋書きを作り足しません。

| 紹介文の選び方 | 対象ジャンル |
|---|---|
| あらすじを優先し、なければ実際の内容・特徴の紹介 | 小説、短編小説、文学作品、映画、漫画、アニメ、ゲーム、戯曲・舞台、ドラマ |
| 実際の内容・特徴の紹介 | 楽曲・歌曲、アルバム、音楽作品、詩、美術作品、ノンフィクション・書籍、その他の作品 |

この分類は候補を探す入口です。作品として確認でき、十分な紹介文がある資料だけを採用します。全作品の網羅や、各ジャンルで必ず同数の問題を生成できることは保証しません。

## 収集する資料

- **青空文庫**：公式の公開作品目録を読み、著作権フラグ「なし」の文学作品と公開本文を取得します。日本小説の分類を優先し、他の文学作品にも順次進みます。本文の作品名を目録と照合し、ルビ・注記・書誌・エピグラフを除いた本文から、まとまりのある文の範囲を選んで要約します。
- **国立国会図書館**：国会図書館サーチの公開APIを、資料種別・NDC分類・一般的なジャンル語で独立して検索します。本についての資料を映画と扱わないよう、図書・録音・映像などの資料種別も確認します。候補の作品名に一致するWikipedia記事を探し、冒頭の作品定義で著作者名と作品種別も確認してから紹介文を取得します。同名の別作品や作者の部分一致は採用しません。書誌に作品種別を確認できる根拠と、十分な「あらすじ：」「内容紹介：」が明示されている場合は、その紹介文から直接生成することもできます。題名・刊行年・目次・版の注記だけから内容を作りません。別途、青空文庫作品の書誌照合も行い、著者1名ごとの完全名と分かる範囲の生没年を確認して参照先を残します。画像資料のOCRやアーカイブ全文の取得・要約は行っていません。資料の閲覧条件は各アーカイブの案内に従います。
- **Wikipedia**：16分類の作品カテゴリ・下位カテゴリと、一般的なジャンル語による全文検索から候補を見つけます。作品名を固定した一覧から選ぶ方式ではありません。カテゴリ所属や検索結果だけで作品と断定せず、記事の冒頭で当該タイトルが実在作品として定義されていることを必須にします。人物・地理・企業・施設・ジャンル・一覧・曖昧さ回避・制作予定・作中だけの架空作品を除外します。物語のあらすじ節を優先し、それが不足する場合や物語以外の作品では、概要・解説・冒頭紹介から作品自身の内容・特徴が分かる文を抽出します。歌詞、詩の全文、曲目・目次、関連する別作品の紹介は避けます。転送名に加え、記事冒頭の題名に付いた読み・原題の注記から別名を取得して伏せ、取得時の版へのリンクを残します。

現在のネット参照先は上記の3系統です。Wikipediaの検索はWikipedia内の全文検索です。NDLから見つけた作品をWikipediaの紹介へ照合する連携はありますが、すべてのWikipedia作品にNDL書誌が付くわけではありません。不特定サイトを巡回する汎用Webクローラーは実装していません。

それぞれ探索位置を保存します。一度の処理の取得回数・追加数には負荷制限がありますが、作品集全体の上限ではありません。次回はページ途中・カテゴリ継続位置・全文検索の位置・目録位置から続きを収集します。取得済みページの残りを保存し、少量の収集でも特定ジャンルが巡回を占有しないよう順番を回します。旧版の小説・映画の探索状態を読み込んだ場合も、継続位置を保って新ジャンルの入口を追加します。Wikipediaは探索を最後まで終えた後、7日経過後に再探索して更新を探します。NDLも探索終了後に再巡回します。青空文庫の目録は最大6時間キャッシュし、再取得で更新を確認した場合は未収集の作品を探します。

検証済みの記事・資料のIDと参照先を使って重複を避けます。題名だけで別作品をまとめないため、著作者や媒体の異なる同名作品も、それぞれの資料を確認できれば保存対象になります。随筆などは小説と断定せず、資料に応じて文学作品・書籍として扱います。

## 自動運転と保存

通常の `npm start` では、サーバー起動時と1時間ごとに収集します。その部屋で未使用の問題が少ない場合は裏で補充し、なくなった場合は新しい問題を収集してから出題します。取得障害では保存済みの問題を使い、繰り返し失敗した場合は再試行まで間隔を空けます。収集は共有し、複数の部屋が同時に不足しても同じ収集を重ねません。

`/health` の `questionCollection` で、自動収集の有効状態、実行中か、定期処理が動いているか、最終開始・完了・成功日時、次回の定期実行予定を確認できます。失敗時は定型の理由を返し、作品名・資料URL・生のエラーは返しません。Renderなどでサーバー自体が休止している間は収集も停止し、次の起動で自動再開します。

収集した問題と探索位置の既定保存先は `server/data/questions/` です。初期問題集は `server/src/questions/bank.json`、固定カタログは明示的な手動テスト用にだけ残しています。自動収集にカタログの手編集は不要です。

保存したデータを保つには保存先のファイルシステムが再起動・再デプロイ後も保持される必要があります。Renderの一時ディスクでは収集分と探索位置が消える可能性があります。その場合も初期データから自動収集を再開します。今回の実装では有料ディスクや新しい保存サービスを契約していません。

以下のコマンドは開発・検証用です。通常運転の自動収集に実行は必要ありません。手元で1回収集する場合：

```bash
cd server
npm run generate:questions
```

既存問題に追加して保存します。再実行すると続きを収集します。1回の処理を大きくする場合、次の件数はその実行の追加目標です。

```bash
npm run generate:questions -- --batch-size 20 --max-requests 60
```

別の場所に、初期問題を使わずネットから収集する場合：

```bash
npm run generate:questions -- --output /tmp/collected-bank.json --state /tmp/collection-state.json
```

`QUESTION_DATA_DIR` で保存先を変更できます。`QUESTION_BANK_PATH` と `QUESTION_DISCOVERY_STATE_PATH` でも個別指定できます。`QUESTION_COLLECTION_ENABLED=false` はサーバーの自動収集を停止する設定です。資料取得には間隔・タイムアウト・回数上限を設け、HTTPSプロキシがある環境では設定を引き継ぐcurlを使います。

Wikipediaへの取得は最低6.5秒間隔にし、次に取得できる時刻を探索状態へ保存します。HTTP 429では `Retry-After` を確認して待機し、指定がない場合は30秒待ちます。待機中はWikipediaへの再試行を控え、青空文庫・NDLの処理を続けます。1回の収集は60秒で区切り、その間に検証できた問題と未処理の探索位置を保存して次回へ引き継ぎます。

## 要約とAI

ネットからの作品発見・目録取得・出典照合には、AIを学習させる必要はありません。通常のプログラムで行います。標準は資料にある完全な文を選び、順序を保って短くする抽出処理です。有料AI APIは呼ばず、新しいAIモデルも学習していません。120〜450文字にまとめ、題名・別名、全半角・空白・不可視文字による表記差を考慮して題名を伏せます。

この方式は生成AIによる自由な言い換えや、長編の筋書きを完全に理解した要約ではありません。読みやすい本文や、作品の題材・構成・特徴を説明する文を優先します。歌や絵画に架空の筋書きを付けません。歌詞・詩の全文、曲目や目次を紹介文として採用しないよう、節と文を検査します。資料の誤り・曖昧な分類・原文の文脈への依存は残るため、出典を答え合わせで確認できるようにしています。

Ollamaに日本語を扱える公開モデルを導入済みなら、要約に使う文の選択をローカルAIに任せることもできます。`MODEL_NAME` を導入済みモデル名に置き換えてください。

```bash
npm run generate:questions -- --ollama-model MODEL_NAME
```

接続先はローカルPCの `http://127.0.0.1:11434` です。モデルを新規学習したものではなく、既存の公開モデルを使う接続です。モデルのダウンロードは自動で行いません。API従量料金は不要ですが、PCの計算資源は使います。モデルの自由な創作文は採用せず、原文にある完全な文と順序を検証します。実モデルの推論はまだ検証していません。

## 出典と答え合わせ

本文の抜粋、本文のSHA-256、資料URL、取得日時、Wikipediaの版番号、青空文庫の著作権情報をサーバー側に保存します。WikipediaにはCC BY-SA 4.0のリンクを表示し、青空文庫には公式公開情報の著作権表示を付けます。

出題中の見出しは「作品紹介」に統一します。作品名、ジャンル名、資料URL、根拠抜粋、探索位置は、回答者への開始・紹介文通知に含めません。CPU確認画面も題名を伏せた紹介文のみです。答え合わせで作品名、確認できたジャンルのラベル、資料リンクを表示します。プレイヤー出題の入力補助は出題者に題名を渡しますが、題名・本文を編集した場合は元資料をその文章の出典として付けません。

`npm test --prefix server` は、ジャンル間の巡回、旧探索状態の移行、全文検索の継続位置、NDLの独立探索と題名・著作者の照合、同名別作品、物語・説明文の抽出、複数回の追加保存、取得失敗、自動補充、収集中のホスト交代と答え合わせまでのジャンル・出典非公開を検証します。

この変更はローカル実装です。公開版への反映はまだ行っていません。
