# 遊んだ履歴とDiscordログイン

最新main `8bea16939d56fb7efbf2a4b0ebc9d4721604c1b0` からの追加。
既存のBetter Auth、名前・アイコン設定、Neonの単一writer保存処理を再利用する。

## 履歴

- ホームの「遊んだ履歴を見る」から、試合一覧・問題と回答の詳細を表示する。
- 試合開始と答え合わせの実際の日時、紹介文、作品名・ジャンル、正解、人間/CPUの回答、投票、既存得点、MVPを記録する。
- 進行中は答え合わせ済みのラウンドだけを表示する。未公開の問題・回答・投票・正解、出典原文、セッションや認証情報は履歴APIへ渡さない。
- ゲストは参加時に受け取った本人用の情報をこのブラウザーへ保持する。席の復帰情報を消す退出操作でも履歴の閲覧情報は消さない。端末保存を消すとゲスト履歴は取り戻せない。保存禁止環境は現在のアプリ起動中のみ。
- ログイン中の参加時はサーバーが検証済みCookieと本人用の情報を照合して紐づける。既存のゲスト履歴は、ログイン後に履歴画面の「この端末の履歴をアカウントに保存」で紐づけられる。
- 紐づけ済み履歴はそのアカウントだけが閲覧する。ログアウト後のゲスト閲覧、別アカウントへの再紐づけ、他人のIDの指定では取得できない。本人用の情報はパスワードと同様に第三者へ渡さない。
- 試合UUIDをキーにしたスナップショットを更新するため、更新・再接続・MVPで重複しない。部屋の退出・削除・24時間期限を越えて保持する。中断した試合は答え合わせ済みの部分だけが残る。
- 一覧は新しい記録から50件ずつ。ゲストの本人用情報は200件単位で照合し、200試合を超えたために古い情報を捨てない。
- 旧スナップショットは互換読込する。既存の席は本人の復帰認証成功後から記録可能。保存されていない過去の試合は復元しない。旧データにない日時は「日時の記録なし」と表示する。
- 記録は既存の部屋スナップショットと同じ保存に含める。保存前に成功配信しない。保存失敗時は履歴とユーザー紐づけを巻き戻す。Neonのwriter交代・不明な保存結果の保護を維持する。
- `ROOM_STATE_PATH` を使うローカル環境では、そのファイルが残る場所へ保存する。既存本番のNeonでは同じ専用DBへ保持する。新規DB・課金・破壊的移行は不要。

制限: 既存の単一プロセス/単一writer方式に合わせた保存であり、履歴も全体スナップショットへ含まれる。利用量が増えて全体保存が重くなった時点で、索引付きの専用テーブルへ移す。接続設定で指定する別のデバッグサーバーの閲覧情報を本番の履歴APIへ送らない。

## Discord

既存のDiscord OAuth APIと名前/アイコン設定を使用し、失敗・キャンセル時はホームのアカウント設定に戻り、再試行できる。プロバイダーの生のエラー説明は画面へ表示せずURLから削除する。

- 既存設定名: `DATABASE_URL`, `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`。
- 既存本番での `BETTER_AUTH_URL`: `https://title-kakko-kari.vercel.app`。
- Discordに登録するcallback: `https://title-kakko-kari.vercel.app/api/auth/callback/discord`。
- スコープは既存Better Authの `identify email` のみ。メールは既存アカウント照合に必要。Bot・サーバー一覧・参加操作などの権限は要求しない。
- Better Authのstate、state Cookie、Origin検査、HttpOnly/Secure/SameSite、既存のセッション失効とレート制限を維持する。追加の永続アクセス権限を要求しない。
- OAuth開始/成功callback/state不正/外部redirect拒否/キャンセル/コード交換失敗/ログアウト/同一ユーザー再ログインを、実Better AuthハンドラーとメモリーDB、模擬Discord HTTP応答で検証する。

2026-10-15の公開API読取結果: Render release `8bea16939d56`、Neon `ready:true`、認証 `ready:false, email:false, discord:false`。コード試験の成功は実Discordの認可・本番ログイン成功ではない。必要な設定名は上記のとおりだが、どの秘密設定が欠けるかは公開statusから特定できない。Discord Developer Portalのcallback登録、必要な既存シークレット設定、利用者本人のOAuth認可と本番での再ログイン検証が残る。今回これらの設定や認可は実行していない。

## 公開境界

今回の作業はPC上の専用コピーと今回専用のDraft候補に保存する。既存リポジトリ・未コミット変更、PR96/100等の候補は変更しない。PRの丸ごと再導入や、以前拒否されたマージ操作の再試行は行わない。

`AGENTS.md` 1–4節と `docs/OPERATING_RULES.md` のCollision preventionに合わせ、既存の所有者Issue #95に今回の明示依頼をCodexによる転記と明記して記録した。新規5パス、関連コードの保護ブロック、今回だけの23パスと現行重複候補のexact-head関係を記録し、Codexの追記自体を所有者の別の追加承認とは扱わない。PR103を含む現在mainを基点として使う。

現行 `scripts/github_coordinator_supervisor.py:414–425,473–475` は依存宣言があってもopen PRとのパス重複を一律停止する。今回の候補をDraftへ同期し同一SHAのnative検査を行うが、この停止条件を迂回してマージ・公開しない。ローカル検証やPonytailレビューをGitHubのCoordinator承認とは扱わない。本番Discord設定の阻害があってもゲストの履歴は動作するが、履歴の公開にも同じ変更管理条件が適用される。

rollbackは今回の専用変更だけの取り消し。保存済みの部屋/履歴データやDBを消さない。
