# タイトルカッコカリ

あらすじや作品紹介を見て「本物のタイトル」を当てるオンライン・パーティーゲームです。出題された作品の紹介文を読み、回答者が本物らしい偽タイトルを提出して投票します。

仕様・制作方針の正本は Notion「タイトルたほいや｜命名クイズゲーム制作」、実装状態の正本はこのリポジトリです。

ホームで名前を入力して部屋を作成・参加でき、ロビーで名前を変更できます。参加に使うのは名前と6桁のルームコードです。時間制限と出題者同意に対応しています。メール/DiscordログインAPIは実装済みですが、未設定のプロバイダーは無効です。公開ログインの設定・確認は [運用資料](docs/NEON_PERSISTENCE_AUTH_20261011.md) に記録しています。

## 現在の構成

- Client: Expo Web / React Native、公開先はVercel。
- Server: Express / Socket.IO、公開先はRender。
- ゲーム中の部屋、参加者、ラウンド、提出、投票、得点はメモリで管理し、保存が成功してから操作を確定します。`DATABASE_URL` が設定されていれば専用Neon DB、未設定ならサーバーのファイルを使います。**Supabaseは使用しません。**
- **サーバーは1プロセス・1インスタンスで運用します。** ファイル保存の `ROOM_STATE_PATH`（既定 `server/data/rooms/state.json`）は、保存領域が残る場合にだけ再起動後の部屋を復元します。Render Freeの通常ファイルは残りません。Neon版の公開保存・インスタンス置換後の復元は、公開releaseと実測結果で確認します。
- 通信切断では席を保持し、自動で同じ部屋へ戻ります。Socket.IOの2分の通知再配信が終わった後も、本人専用の復帰情報で進行を復元します。ページ再読み込み後はホームの「落ち戻り」を選びます。「部屋から出る」は即時退出し、復帰情報を無効にします。全員がオフラインになった部屋は24時間で期限切れになります。接続中の部屋に放置時間の上限はありません。詳しくは [接続調査と復帰の説明](docs/SESSION_RECOVERY.md) を参照してください。

移行理由・責務の棚卸し・検証範囲は [移行記録](docs/SUPABASE_REMOVAL.md)、公開版の状況は [Release Status](docs/RELEASE_STATUS.md) を参照してください。

## 対応人数

| 構成 | 最低人数 | 最大人数 |
|---|---|---|
| 人間とコンピュータの合計 | **2席** | 6席 |

ホストはロビーでコンピュータ回答者を0〜5人に増減できます。人間1人＋コンピュータ1人から対戦でき、人間1人＋コンピュータ4人でも遊べます。人間が1人のときはコンピュータが作品を出題します。名前の入力を終えていない参加者がいる間は開始を待ちます。

コンピュータは紹介文にある言葉をタイトルらしい句に組み合わせ、提出開始時に偽タイトルを自動で1つずつ提出します。正解・出典・他の回答は生成に渡さず、投票・出題・既知宣言は行いません。欺き票とMVPは既存の採点どおり加点します。外部AIサービスや追加の設定は不要ですが、言葉と句の組み合わせによる生成なので表現の幅には限りがあります。

## 遊び方

1. ホストがホームで名前を入力して部屋を作り、6桁コードを共有する。
2. 参加者はホームで名前と6桁コードを入力して部屋に入り、人間とコンピュータを合わせて2〜6席で開始する。
3. 紹介文を提示して、人間の回答者が「知らない」を選ぶのを待つ。出題者は「知ってる／知らない」を選ばず、回答者の確認だけで先へ進める。CPU出題ではホストも回答者として選ぶ。「知ってる」があれば、プレイヤー出題では出題者、CPU出題ではホストが確認して選び直す。作品を選び直したら、前の作品・答え・ジャンルの表示を消す。取得障害時は人間が2人以上ならホストが「手動で出題する」で、この回の文章と答えを入力できる。得点と残りラウンドは保持し、次の回は再びCPU出題を試す。
4. 回答者が偽タイトルを提出し、本物と混ざった候補から投票する。自分の偽タイトルには投票できない。出題者は回答・投票を行わない。
5. 出題者は出題後も本物の作品名と集まったタイトル案を確認できる。回答者には答え合わせまで正解を伏せる。答え合わせでは作品名と、自動取得した問題のジャンル・出典を表示する。正解に1点、偽タイトルに投票された数だけ加点する。プレイヤー・手動出題ではMVPに1点を贈ってから次のラウンド・最終結果へ進む。出題者が退出した場合はホストがMVPを選ぶ。
6. プレイヤー出題は人間全員1回ずつ、CPU出題は指定ラウンドを終えたら最終順位を表示する。

## 無料の自動出題

CPU出題とプレイヤー出題の補助は、毎回ネット検索と個別作品ページの取得を行います。特定のドメインや固定作品名に限定せず、書店・映画作品情報・ゲームストアの現在の一覧も使います。保存問題集の在庫や過去の収集失敗に依存しません。

ジャンル指定ありでは、出題者（CPU出題ではホスト）が「ノンジャンル・小説・映画・漫画・ゲーム」から選びます。ノンジャンルは種類を限定せず検索し、小説には短編小説・文学作品も含みます。選択は再検索・再接続でも保持します。

公式に流通する作品だけをランダムお題に採用します。書籍は当該作品の出版社・有効なISBN・発売日、映画は配給/公式配信元・公開日、ゲームは公式販売ページの発売日・有料販売・開発元/パブリッシャーを確認します。未出版のウェブ投稿、同人誌、自費/自主出版、個人の自主配布、フリーゲーム、流通を確認できない作品は除外します。検索語・ページ・候補順を分散し、小規模な公式作品の確認を優先します。広い販売・評価・映像化やシリーズ派生の根拠がある作品と、既存の有名作品集の題名・別名は別サイトや別ジャンルでも除外します。認知度不明の確認済み作品は、小規模作品を探した後の補助候補として使います。

紹介文は原文の順序で120〜280文字に抽出します。題名を含む文や価格・感想・制作報告を除き、番号付きの続編・部編区分は採用しません。ホストがロビーで「ジャンル指定あり/なし」を選べます。ありでは毎回、出題者（CPU出題ではホスト）がジャンルを先に選び、そのジャンルの作品から問題を用意します。自動取得は選択に合わせて検索し、見つからなければ再検索またはジャンルを選び直せます。手動入力でも先にジャンルを選びます。出題時からジャンルを表示し、なしでは答え合わせまで伏せます。正解の題名と出典は、どちらのルールでも答え合わせまで非公開です。

ネットワークの全面障害や外部サイトの全面拒否まで成功を保証することはできません。その場合は取得失敗を表示して再検索でき、任意で手動出題もできます。有料API・新しい依存パッケージ・作品リストの手入力は不要です。従来の収集/保存CLIは別用途として残します。詳しくは [自動出題の説明](docs/AUTOMATIC_QUESTIONS.md) を参照してください。

## ローカル起動

Node.js 20.3〜24を使用します。データベースの準備は不要です。

```bash
cd server
npm ci
npm start
```

`server/.env` は任意です。使える設定は `PORT`（既定3000）、`NODE_ENV`、`ALLOW_THREE_PLAYER_DEV`、`ALLOWED_ORIGINS`（カンマ区切りのWeb origin）、`ROOM_STATE_PATH`（部屋の保存先）、`QUESTION_DATA_DIR`（収集した問題・探索状態の保存先）、`QUESTION_BANK_PATH`、`QUESTION_DISCOVERY_STATE_PATH`、`QUESTION_COLLECTION_ENABLED=false`（自動収集停止）です。公開運用では `ALLOWED_ORIGINS` にClientのURLを指定してください。古いSupabaseの環境変数は読み込みません。Secret値をリポジトリへ記録しないでください。

別のターミナルでClientを起動します。

```bash
cd client
npm ci
npm run web
```

ホームの「接続設定」を開き、接続先を `http://localhost:3000` に変更してください。スマートフォン実機ではPCのLAN上のIPを指定します。既定の接続先は `client/src/config.js` のRender URLです。`EXPO_PUBLIC_SERVER_URL` は読み込みません。

## 検証とWebビルド

```bash
python scripts/public_export_guard.py .
python scripts/validate_repository.py
python -m unittest discover -s tests
npm ci --prefix server
npm ci --prefix client
npm test --prefix server
npm run build:web --prefix client
```

通信テストは実際のExpress / Socket.IOサーバーを起動し、4・5・6人の両出題モードを最終順位まで検証します。ゲームのテストでは自動収集を停止して固定資料を使い、答え合わせまでのジャンル・出典非公開、自己投票・重複出題の拒否、出題者が抜けた後にホストが次ラウンドへ進めること、最後の1人への終了通知と得点の保持を確認します。ブラウザー用の知らせと確認のボタンも検証します。収集のテストではジャンル巡回・全文検索のページ継続・旧探索状態の移行・青空文庫目録・国会図書館の独立探索と著作者照合・紹介文抽出・同名別作品・追加保存・自動補充・取得障害を検証します。Socket.IOテストクライアントは既存のClient依存を使うため、両方の `npm ci` が必要です。

Web出力は `client/dist/` です。VercelのProject Root Directoryは `client`。単一Renderサーバーへの接続とWebSocket / polling双方の許可が必要です。

復帰の通信・認証・保存・強制再起動は `tests/session-recovery.cjs` で検証します。実時間の放置試験は `npm run test:session-soak --prefix server` で実行します。実際に25分待ち、人間4人のpolling接続と人間3人＋コンピュータ1人のWebSocket接続を保持した後、回答・投票・MVP・次ラウンドを確認します。既定の短時間テストでは、この待機を省略しています。

## デザイン・開発運用

ゲーム名は「タイトルカッコカリ」、題名の絵では「タイトル（仮）」と表します。最初の画面は暖かいクリーム色を背景に、画像生成で作ったロゴとネコ、読みやすい日本語の文字を使います。「あらすじ → ウソをつくる → 本物はどれ？」の短い見本は、映画・小説・漫画・ゲームで切り替えられます。この切り替えは遊びの紹介用で、本番の問題のジャンルを選ぶ機能ではありません。スマートフォンではロゴ横のネコを小さくし、部屋を作る・入るボタンを見本より先に置きます。見た目の決まりは [題名の画面](docs/TITLE_SCREEN.md) と [UIの決まり](docs/UI_DESIGN_SPEC.md)、開発運用は `AGENTS.md` と `docs/OPERATING_RULES.md` を参照してください。

Neon 永続化とメール/Discord 認証の非秘密設定・未設定項目・復帰と切戻し手順は [運用資料](docs/NEON_PERSISTENCE_AUTH_20261011.md) を参照してください。
