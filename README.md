# タイトルカッコカリ

あらすじや作品紹介を見て「本物のタイトル」を当てるオンライン・パーティーゲームです。出題された作品の紹介文を読み、回答者が本物らしい偽タイトルを提出して投票します。

仕様・制作方針の正本は Notion「タイトルたほいや｜命名クイズゲーム制作」、実装状態の正本はこのリポジトリです。

## 現在の構成

- Client: Expo Web / React Native、公開先はVercel。
- Server: Express / Socket.IO、公開先はRender。
- ゲーム中の部屋、参加者、ラウンド、提出、投票、得点はサーバーのメモリで管理します。**Supabase、データベースの接続設定、新しい保存サービスは不要です。**
- **サーバーは1プロセス・1インスタンスで運用します。再起動・休止・再デプロイ時には部屋と得点が消えるため、部屋を作り直してください。** 最後の参加者が切断した部屋は削除します。
- 途中切断後の本人確認付き復帰、履歴保存、複数インスタンスでの状態共有は未対応です。切断後はホームへ戻り、新しい接続として扱います。Issue #55の候補では、ゲーム中も「部屋から出る」で退出でき、遊ぶ人が1人だけになった場合は終了の知らせとホームへ戻るボタンを表示します。

移行理由・責務の棚卸し・検証範囲は [移行記録](docs/SUPABASE_REMOVAL.md)、公開版の状況は [Release Status](docs/RELEASE_STATUS.md) を参照してください。

## 対応人数

| 環境 | 最低人数 | 最大人数 |
|---|---|---|
| 通常（production / staging / test / その他） | **4人** | 6人 |
| ローカル開発テスト（明示opt-in） | 3人 | 6人 |

3人プレイはServerが `NODE_ENV=development` かつ `ALLOW_THREE_PLAYER_DEV=true`、Clientが開発ビルドかつ `EXPO_PUBLIC_ALLOW_THREE_PLAYER_DEV=true` の場合だけ有効です。2人以下は常に拒否します。

## 遊び方

1. ホストが部屋を作り、6桁コードを共有する。
2. 4〜6人でプレイヤー出題またはCPU出題を開始する。
3. 両モードとも、紹介文を提示して全員の「知らない」宣言を待つ。「知ってる」があれば、プレイヤー出題では出題者、CPU出題ではホストが確認して選び直す。取り下げた問題の正解を全員に表示する。CPUの候補が不足した場合はホストが「手動で出題する」で、この回の文章と答えを入力できる。得点と残りラウンドは保持し、次の回は再びCPU出題を試す。
4. 回答者が偽タイトルを提出し、本物と混ざった候補から投票する。自分の偽タイトルには投票できない。出題者は回答・投票を行わない。
5. 答え合わせで作品名を確認し、自動取得した問題ではジャンル・出典も表示する。正解に1点、偽タイトルに投票された数だけ加点する。プレイヤー出題では出題者がMVPに1点を贈れる。
6. プレイヤー出題は全員1回ずつ、CPU出題は指定ラウンドを終えたら最終順位を表示する。

## 無料の自動出題

サーバーが汎用Web検索（DuckDuckGo／Bing）で、特定サイトを指定せず作品を探します。その年の新作・新刊、話題作、自主制作作品などの検索も巡回し、出版社・書店・作品公式・紹介サイトなどの公開HTTPSページから作品名と十分な紹介文を確認して問題を作ります。Amazonも候補の一例で、唯一の収集先ではありません。Wikipediaの記事は必須にしません。検索結果の短い説明だけから内容を作らず、取得制限・認証・本文不足のページは採用しません。従来のWikipediaの作品カテゴリ・全文検索、青空文庫の公開目録、国立国会図書館サーチの資料種別・分類検索も続けます。小説・映画だけでなく、漫画、アニメ、ゲーム、ドラマ、音楽、詩、美術、書籍など16分類を対象にし、記事・資料が実在作品を紹介していることを確認します。国会図書館の候補は、作品名と著作者が一致するWikipediaの解説、または書誌内の明示された十分な内容紹介を使います。資料不足や照合不一致の候補は出題しません。

標準では資料の紹介文から完全な文を原文の順序で選び、題名・別名を含む文を省いて120〜280文字で表示します。レビュー・価格・購入案内・著者略歴・制作経緯・資金募集・旧仮名遣い・古典文体を除外し、保存済み問題にも同じ検査と短縮を適用します。青空文庫の本文抜粋を紹介文にせず、作品名と著作者を確認した現代語の解説を使います。手入力の紹介文も280文字までです。物語にはあらすじを優先し、曲・絵画などには実際の特徴・内容の紹介文を使います。出題中の見出しは「作品紹介」に統一し、回答者にジャンル名・作品名・出典を明かすのは答え合わせからです。CPU出題とプレイヤー出題の入力補助が同じ収集機能を使います。

出典で個人制作・自主出版・小規模制作を確認できる作品だけを自動出題と入力補助に使います。個人制作・自主出版を優先し、大きなレビュー・販売規模や映像化の根拠がある作品、同梱の有名作品は除きます。ジャンルと出典ドメインを分散して選び、候補不足でも一般作品や初期問題で埋めません。知名度の実測や、誰も作品を知らないこと、全サイトからの取得成功を保証する仕組みではありません。

通常の `npm start` で自動収集が始まり、1時間ごとと未使用問題が少なくなったときにも続きから収集します。作品リストの手編集や収集コマンドの手動実行は不要で、収集済み作品の総数に上限は設けません。ジャンルごとに巡回しますが、ネット上の全作品を発見・出題できることを保証するものではありません。有料AI APIは使わず、新しいAIモデルも学習していません。PC上のOllamaを利用する任意のローカルAI接続も用意しています。収集と保存、要約品質の検証範囲は [自動出題の説明](docs/AUTOMATIC_QUESTIONS.md) を参照してください。公開状況は [Release Status](docs/RELEASE_STATUS.md) と統合PRで確認します。

## ローカル起動

Node.js 20.3〜24を使用します。データベースの準備は不要です。

```bash
cd server
npm ci
npm start
```

`server/.env` は任意です。使える設定は `PORT`（既定3000）、`NODE_ENV`、`ALLOW_THREE_PLAYER_DEV`、`ALLOWED_ORIGINS`（カンマ区切りのWeb origin）、`QUESTION_DATA_DIR`（収集した問題・探索状態の保存先）、`QUESTION_BANK_PATH`、`QUESTION_DISCOVERY_STATE_PATH`、`QUESTION_COLLECTION_ENABLED=false`（自動収集停止）です。公開運用では `ALLOWED_ORIGINS` にClientのURLを指定してください。古いSupabaseの環境変数は読み込みません。Secret値をリポジトリへ記録しないでください。

別のターミナルでClientを起動します。

```bash
cd client
npm ci
npm run web
```

ホームの「接続設定」を開き、接続先を `http://localhost:3000` に変更してください。スマートフォン実機ではPCのLAN上のIPを指定します。既定の接続先は `client/src/config.js` のRender URLです。`EXPO_PUBLIC_SERVER_URL` は読み込みません。

## 検証とWebビルド

```bash
python scripts/public_export_guard.py .
python scripts/validate_repository.py
python -m unittest discover -s tests
npm ci --prefix server
npm ci --prefix client
npm test --prefix server
npm run build:web --prefix client
```

通信テストは実際のExpress / Socket.IOサーバーを起動し、4・5・6人の両出題モードを最終順位まで検証します。ゲームのテストでは自動収集を停止して固定資料を使い、答え合わせまでのジャンル・出典非公開、自己投票・重複出題の拒否、出題者が抜けた後にホストが次ラウンドへ進めること、最後の1人への終了通知と得点の保持を確認します。ブラウザー用の知らせと確認のボタンも検証します。収集のテストではジャンル巡回・全文検索のページ継続・旧探索状態の移行・青空文庫目録・国会図書館の独立探索と著作者照合・紹介文抽出・同名別作品・追加保存・自動補充・取得障害を検証します。Socket.IOテストクライアントは既存のClient依存を使うため、両方の `npm ci` が必要です。

Web出力は `client/dist/` です。VercelのProject Root Directoryは `client`。単一Renderサーバーへの接続とWebSocket / polling双方の許可が必要です。

## デザイン・開発運用

ゲーム名は「タイトルカッコカリ」、題名の絵では「タイトル（仮）」と表します。最初の画面は暖かいクリーム色を背景に、画像生成で作ったロゴとネコ、読みやすい日本語の文字を使います。「あらすじ → ウソをつくる → 本物はどれ？」の短い見本は、映画・小説・漫画・ゲームで切り替えられます。この切り替えは遊びの紹介用で、本番の問題のジャンルを選ぶ機能ではありません。スマートフォンではロゴ横のネコを小さくし、部屋を作る・入るボタンを見本より先に置きます。見た目の決まりは [題名の画面](docs/TITLE_SCREEN.md) と [UIの決まり](docs/UI_DESIGN_SPEC.md)、開発運用は `AGENTS.md` と `docs/OPERATING_RULES.md` を参照してください。
